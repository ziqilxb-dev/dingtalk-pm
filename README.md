# 钉钉与产品工作流

把这个仓库链接发给你的 AI，让它安装一次，以后直接描述要做的工作。

> 请阅读这个仓库的 README.md、INSTALL_FOR_AI.md 和 SKILL.md，把完整 skill 安装到你当前工具支持的位置，检查依赖并完成自检。需要钉钉登录时让我操作。不要创建定时任务，也不要修改我的业务文档。

安装后这样用：

- “看看我和某人最近关于邮件匹配的讨论，整理结论和待确认项。”
- “根据这个群今天确认的方案，更新这份钉钉 PRD。”
- “帮我做这个需求的 PRD、原型、流程图和验收清单。”

## 工作方式

CLI按需读取指定会话；对影响结论的缺失消息，在宿主支持电脑操作时补读客户端。信息整理保留依据，区分事实、决定和建议，然后进入包内完整的产品工作流。执行到用户明确要求的范围，不自动监控、发消息或改文档。

## 谁可以用

需要支持本地执行和文件操作的AI工具，以及Python 3.9+。包内安装器适配Windows、macOS、Linux的x64/ARM64，自动下载对应官方DWS并校验。每个人登录自己的钉钉。

能阅读GitHub链接的AI不一定能安装skill。支持原生skill的工具使用自己的安装目录；没有原生skill机制但有本地执行能力的工具，可以把仓库放到工作区，按SKILL.md执行。只有网页聊天、不能执行本地命令的工具只能阅读说明，不能直接访问本机钉钉。

客户端补读另外需要宿主电脑操作工具、钉钉客户端和系统权限；没有这些能力就保留缺口，接受用户提供的原文/截图，CLI和PM功能仍可使用。

## 给 AI 的安装入口

[INSTALL_FOR_AI.md](INSTALL_FOR_AI.md) 包含安装、检查、登录和完成验证流程。不要只下载SKILL.md：scripts、assets、references、agents和bin校验清单都需要保留。

[SKILL.md](SKILL.md) 是日常执行入口；[PACKAGE.md](PACKAGE.md) 是手动使用说明；[平台验证范围](references/compatibility.md) 如实区分资产验证与真机测试。
