# 客户端补读

只用当前提供的cua_repl及其文档API操作UI；不安装快捷键、常驻采集，不用AppleScript替代。

1. 从证据包选出与主题有关的缺失消息，记录时间、发送人、前后已知原文和引用。集中处理，避免反复切窗。
2. 先确认宿主提供电脑操作工具。macOS用cua.listApps发现应用并以返回ID连接，实测ID 5ZSL2CJU2T.com.dingtalk.mac 仅是本机线索。Windows/Linux按当前工具文档列出窗口，用真实windowId连接，不能沿用macOS的应用ID、坐标或快捷键。
   宿主没有电脑操作工具、没有钉钉客户端或尚未登录时，保留缺口并请用户提供相关原文/截图；其他可读信息仍可整理。不得声称换系统后补读必然可用。
3. 核对聊天标题。已显示目标就直接读辅助功能树；否则依真实UI搜索人/群、关键词或日期。不能凭猜测点击，更不能将搜索词输进发送框。
4. 优先辅助功能文字，必要时截图。准确说明截图涉及屏幕捕获，不是持续录屏；不能说整个补读是纯后台接口。
5. UI通常无消息ID。结合会话、发送方向、时间区域、前后已知消息或引用匹配。不能唯一对应时不绑定ID；秒级时间取自CLI要明确，不能说屏幕显示了秒。
6. 补读保存在client-supplements.json，CLI原记录不覆盖。补几条不代表全部缺口消失；补读后重新评估结论及上下文。

结构：
```json
{"items":[{"conversation_id":"observed-id","message_id":"matched-id-or-null","text":"实际原文","method":"accessibility","observed_at":"ISO8601","match_basis":"会话、发送方向、相邻原文","match_status":"matched","time_source":"CLI"}]}
```

不发消息、不转发撤回、不改设置。需要额外权限或用户登录时说明具体阻碍。必要前台操作提前告知，不循环激活Codex抢回焦点；不要求用户重复批准已授权的读取。
